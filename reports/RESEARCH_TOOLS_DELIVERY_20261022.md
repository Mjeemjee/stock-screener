# 研究工具接入交付清单

日期：2026-10-22。

## 已实现

| 改动 | 背景 | 目的与实际作用 |
|---|---|---|
| 新实验假设卡 | 只有“看好某个公式”不足以验证想法 | 新手工提案与后续 DeepSeek 提案需写依据、失败条件、数据/执行限制；启动时卡片进入原有定义哈希，后改会被发现 |
| 研究复核页 | 赚钱、跑赢指数、优于旧策略是不同的事 | 在因子研究详情中单列盈亏、跑赢次数、缺价、未到期、现金、不重叠时段；独立家族以研究池等权为对照，有父策略则对比父策略 |
| 压力与证据检查 | 单看平均收益容易误判 | 显示成本加大、样本、完整率、不重叠时段、最差一期和原关卡的不确定性检查；没有证据时显示待验证 |
| DeepSeek 输入补充 | 模型需要知道结果的局限 | 在原来的固定样本上下文中加入只读复核摘要，明确新建议不能更改原成本、预算、审批和考试关卡 |
| 复核记录下载 | 页面描述需要能对应实际来源 | 下载包含定义、引擎、政策、原关卡与派生证据哈希的 JSON；这是来源绑定，不是盈利保证 |
| 云端流程接入 | 本机装技能不会自动改变网站 | 每日扫描、发布、人工研究审核均会生成只读复核结果；新启动入口强制校验卡片 |

## 没有改变的事

- 记分引擎和引擎版本所覆盖的八个源文件均未修改；没有暂停或重启旧研究。
- 下一尚未开盘入场、交易日周期、成本、固定权重、缺价未知、既定关卡和研究数量预算保持不变。
- 旧实验只保留原始说明，没有补造“当初已经声明”的失败条件。自动公式研究没有单独冻结卡片时也如实说明。
- 没有替换成第三方复盘计分器，没有引入付费行情/券商依赖，没有自动交易。
- 本地已有的 `screener_results.json` 和 `tracking.json` 改动不纳入本次提交。

## 如何验证

1. 进入“实验室 → 因子研究”，选择实验，再打开“研究复核”。当前没有到期结果时应显示未知/待验证，而不是凭空出现收益。
2. 在“研究提案”建立新提案。依据、失败条件、数据限制未填齐时不能导出；填写后可以保存与下载，但不会自动启动。
3. 导入旧提案，补齐卡片后再导出。通过原仓库权限审核后才创建新实验；原关卡不变。
4. 下载复核记录，核对实验 ID、定义哈希、来源日期和关卡哈希是否对应当前实验。
5. 新结果到期后，赚钱次数不必等于跑赢指数次数；缺价期不应计为零收益，重叠期次不应全部计作独立考试。
